# 点餐台 · 用户流程 User Case

> 用例编号：UC-2026-1019-01 ｜ 系统：麦当劳点餐台（营养光谱 & 旋律）原型 ｜ 场景：堂食顾客自助点餐

## 角色（Actor）

| 角色 | 说明 |
|---|---|
| 顾客 | 到店点餐的消费者，使用手机操作 |
| 系统 | 点餐台服务（menu / portrait 两个能力） |

## 前置条件

- 顾客可访问点餐台页面（本机 `http://127.0.0.1:8765/`）
- 菜单数据来自麦当劳官方单品目录（26 款，营养字段齐全）

## 主流程（Happy Path）

### UC-1 浏览与点餐

1. 顾客进入点餐页，看到品牌顶栏（无其他入口按钮）与三个分类标签：汉堡·卷 / 小食 / 饮品
2. 顾客切换分类浏览菜品卡片（名称、热量、蛋白质、价格、色块插画）
3. 顾客点「+ / −」调整数量，底部结算条实时显示件数与合计金额
4. 系统约束：至少选择 1 件，「下单」按钮才可点击

### UC-2 下单与取餐号

1. 顾客点「下单」
2. 系统校验 SKU、合计价格与热量，分配取餐号（A + 3 位流水，全局递增、重启不重复）
3. 页面切换到取餐号页：大号取餐号 + 小票摘要（菜品明细 · 合计 · 预计 3 分钟）

### UC-3 营养光谱与旋律的询问

1. 取餐号页下方显示一行文字：「想知道你的餐品营养光谱和旋律吗？」
2. 顾客可选：
   - **想看** → 进入 UC-4
   - **不用了** → 留在本页（保留「再点一单」入口）

### UC-4 光谱 + 旋律页

1. 页面顶部常驻吸顶栏：返回按钮 + **取餐号** + 重新点餐按钮
2. 系统生成营养光谱（约 1.7s）：按 SKU 营养数值聚合六项达成率，以取餐号为指纹铭文渲染带饼图的「我的营养光谱」（同单幂等：同一订单重复进入，图片完全一致）
3. 系统生成旋律（约 0.7s/曲风）：营养数值 → 音乐要素（调式=钠钙比、BPM=能量达成率、句长音高力度=各营养素达成率、钙不足结尾悬置、装饰音=指纹）
4. 页面布局自上而下：
   - 营养光谱图（点「放大查看」可全屏）
   - 「分享这张营养光谱」按钮 → 底部分享面板（微信好友 / 小红书 / 保存图片 / 复制文案）
   - 曲风切换：民乐 / 爵士 / 摇滚（各曲风只生成一次，之后缓存）
   - 播放器（播放/暂停、进度拖拽）
   - 一行粗体概括（大众版第一句）
   - 「这是你专属的在这一刻的旋律」+ 两颗爱心
   - 脚注（曲风 · BPM · 时长 · 糖为推算值备注）
5. 顾客切曲风 → 按需生成并缓存，播放器同步换音频

### UC-5 分享

1. 顾客点「分享这张营养光谱」，底部弹出分享面板，副标题为「取餐号 · 热量 · 最高营养素」
2. 四个入口行为：
   - **微信好友**：复制分享文案 → 提示去微信粘贴
   - **小红书**：复制带话题文案（#麦当劳 #营养光谱 #今天吃什么）→ 提示去小红书发布
   - **保存图片**：下载光谱 PNG（文件名含取餐号）
   - **复制文案**：复制全文案
3. 约束说明：普通网页无法直接调起微信 / 小红书发布页，本原型采用「备好图片 + 文案 → 去 App 粘贴」方案

### UC-6 收尾

1. 顾客从光谱页点「‹」返回取餐号页，或点「⌂」重新点餐
2. 重新点餐 → 清空购物车、取餐号流水 +1，回到 UC-1
3. 数据留存：每单产物（spectrum.png、三曲风 wav、meta.json）保存在 `out/<订单号>/`，订单台账写入 `data/orders.json`

## 备选流（Alternative Flows）

| 编号 | 触发 | 行为 |
|---|---|---|
| A1 | 顾客直接打开 `/?demo=1` | 系统自动下一份样例单，直达光谱+旋律页（演示用） |
| A2 | 生成失败（如服务重启丢缓存） | toast 提示错误，返回取餐号页，可重试 |
| A3 | 顾客在点餐页未选任何商品 | 「下单」按钮置灰不可点 |

## 后置条件

- 订单与产物落盘，服务重启后取餐号继续递增
- 同一订单号 + 曲风的请求直接返回缓存（`cached: true`），保证图曲一致性

## 非功能要点

- 移动端优先：390×844 布局、安全区适配、触控目标 ≥44px
- 生成耗时合计约 2.4s，用加载转场掩盖；切曲风约 0.7s
- 零第三方依赖：后端 Python 标准库，前端无框架无 CDN
